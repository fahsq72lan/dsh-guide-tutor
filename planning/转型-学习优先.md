# 转型：引导为旁路，学习为主路

> 状态：**待启动**。用户 2026-11-13 20:23 拍板方向，同时明确「但不是现在」。
> 提交方式：转型完成后走 `tools/publish.ps1` squash 进 main，推 GitHub（`fahsq72lan/dsh-guide-tutor`）。

## 一句话

把插件从「帮你把事办完」改成「教到你自己会」；需要时再退回引导。

## 为什么转

1. **引导是通用能力**：能联网、能看屏幕、能给下一步的工具有很多，它不是差异化。
2. **教学是稀缺能力**：看得见屏幕 + 能在屏幕上画标注 + 能判断你哪一步错了，这个组合公开产品里没有完全对应的。
3. **用户的真实处境**：他 2026-11-13 自己说「引导本质是快速帮用户在陌生领域完成任务，学会截然不同」——两者优化方向相反，混在一起两边都不讨好。
4. 插件现在功能多而不深（清单/番茄钟/专注环/目标/指令/日记/视频/摄像头），主线已经模糊；转型正好是一次减法。

## 转成什么样

| 场景 | 现状 | 转型后 |
| --- | --- | --- |
| 用户问「这个怎么弄」 | 直接给步骤、画标注、收工 | 先问一句「你是要办完还是要学会」 |
| 用户要办完 | 主路径 | **旁路**：快速给路径，不要求复述 |
| 用户要学 | 不存在 | **主路径**：演示 → 你来做 → 我纠错 → 你复述 → 收尾测验 |
| 收尾 | 一句「好了」 | 记一次练习：练了什么、卡在哪、下次复习点 |

## 要动的部分（骨架，不是最终设计）

1. **入口判断**：`guide_teach` 或新的开场工具加 `intent`（do / learn），默认询问一次，记住本次会话选择。
2. **学习主流程**：
   - 演示（全标）→ 用户操作（截屏判定）→ 纠错（错误位置画圈 + 一句话）→ 复述（不看屏幕）→ 小测（1 题）；
   - 判定用「这次有没有做对 + 说得出来吗」两个信号，不追求分数。
3. **引导旁路**：保留现有「截屏 → 标注 → 说明 → 收工」，但入口收窄为「用户明确要办完」或「学习流程中求助」。
4. **练习题/错题本**：失败截图进知识库 `薄弱点/`，开场抽一条复习。
5. **进度视图**：哪些技能点学过、复述过、隔几天复述过——这是「学会」的唯一证据。
6. **coach 插件复用**：番茄钟/清单本来就是练习脚手架，转型后与 tutor 打通（一次专注 = 一个技能点）。

## 不做什么

- 不在引导流程里强制撤支架（会把人烦走）。
- 不做分数、徽章、排行榜（和「学会」无关）。
- 不为转型新增管理类功能，先减法再加。

## 验收（初版）

- 用户说「教我怎么用 XX」，走学习流程，能被判定「做对了 / 没做对」并给出具体纠错；
- 收尾时能看到「这次练了什么、卡在哪」；
- 隔天再问同一条，插件能调出上次的卡点；
- 引导场景的响应时间不劣于现在（不能因为转型变慢）。

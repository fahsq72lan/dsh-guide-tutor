# guide-tutor / guide-coach 项目结构表

> 版本：2026-11-13（转型前基线）
> 用途：开工前对齐结构；后续加功能按此表挂载，不另起炉灶。

## 0. 定位与决策权

| 项 | 约定 |
| --- | --- |
| 产品定位 | 屏幕教学助手（看得见屏幕、能在屏幕上画、能判断你哪步错了） |
| 当前形态 | 引导为主（帮你把事办完），学习为辅 |
| 目标形态 | 学习为主路，引导为旁路（见 `planning/转型-学习优先.md`） |
| 大方向决策 | **用户主导约 80%**，AI 只提建议（约 20%），最终由用户拍板 |
| 技术底线 | 本地优先、不录屏不上传、PowerShell 浮层 + Node 宿主 |

## 1. 四层结构（延展的地基）

```
┌─────────────────────────────────────────────┐
│  入口层    DSH 工具 / HTTP API / 面板按钮      │  ← 可增删，不影响下层
├─────────────────────────────────────────────┤
│  业务层    教学流程 · 练习流程 · 清单 · 专注     │  ← 转型主要动这里
├─────────────────────────────────────────────┤
│  能力层    截屏 · 标注 · 口播 · 状态 · 存储     │  ← 稳定，尽量不动
├─────────────────────────────────────────────┤
│  平台层    WPF 浮层 · TTS · 定时器 · 文件系统   │  ← 与业务无关
└─────────────────────────────────────────────┘
```

**延展原则**：新功能只允许往「入口层」和「业务层」加；往能力层和平台层加东西要单独论证。

## 2. 功能清单

### 2.1 平台层（不动）

| WPF 浮层 | `native/overlay.ps1` | 画球、面板、标注、清单卡片、字幕 |

## 3. 联动强度

图例：**●●● 强**（缺一方就不能工作）／**●● 中**（能工作但效果明显变差）／**● 弱**（仅数据或提醒上的关联）

| 从 → 到 | 强度 | 说明 |
| --- | --- | --- |
| 截屏 → 标注 | ●●● | 标注以截图为坐标系，没截图不能画 |
| 标注 → 面板 | ●●● | 面板与标注同时出现、同时消失 |
| 标注 → 口播 | ●●● | 字幕贴在标注旁边 |
| 教学 → 收尾 | ●●● | 收尾就是清教学状态 |
| 状态 → 一切 | ●●● | state.json 是唯一真相，读写都要过它 |
| 浮层 → 一切 | ●●● | overlay 挂了，所有界面全没 |
| 清单 → 专注环 | ●●● | 专注环按清单条目的时间触发 |
| 指令 → 清单 | ●●● | 指令写入/催办的是清单条目 |
| 专注环 → 口播 | ●●● | 到点必须说话，否则专注环没意义 |
| 知识库 → 教学 | ●● | 教学时查资料可提升质量，但不查也能教 |
| 视频 → 知识库 | ●● | 视频要点可存进知识库，不存也能看 |
| 摄像头 → 口播/教学 | ●● | 摄像头结论常以语音给出 |
| 日记 ← 一切 | ● | 只是旁路记录，不影响主流程 |
| 时钟 ← 一切 | ● | 只是时间来源 |
| 教学 → 清单 | ● | 教完可以顺手记一条，但不强制 |
| 教学 → 练习（转型新增） | ●●●（目标） | 转型后变成主链路 |

## 4. 转型后的目标结构（学习为主路）

```
用户发起
   │
   ├─ 判断：办完 / 学会 ──────────┐
   │                              │
   ▼ 学会（主路）                 ▼ 办完（旁路）
演示（全标）                     快速给路径
   ↓                              ↓
你做（截屏判定）                 收工
   ↓
纠错（错误位置画圈 + 一句话）
   ↓
复述（不看屏幕）
   ↓
小测（1 题）
   ↓
记录（练了什么、卡在哪）
   ↓
错题本 / 复习点
```

**新增/改造的功能（转型时）**：

| 功能 | 层 | 作用 | 与谁联动 |
| --- | --- | --- | --- |
| 意图判断 | 入口 | 办完 / 学会 | 全部入口工具（强） |
| 练习会话 | 业务 | 一次「学—练—考」的状态 | teach、screen、say、kb（强） |
| 练习判定 | 业务 | 截屏对比，判断对不对 | 截屏、标注（强） |
| 复述检验 | 业务 | 记录用户口述质量 | 面板 ask 通道（中） |
| 错题本 | 能力 | 失败截图 + 卡点，进 kb | kb、教学（中） |
| 进度视图 | 入口 | 技能点学到什么程度 | 练习会话、kb（中） |

## 5. 延展规则（加新功能时照这个来）

1. **先定位**：它属于哪一层？能力/业务/入口，写进上表；
2. **只写 state**：新功能的状态放 `state.json` 的一个顶层键，不要另建文件（除非是大对象，如 kb、videos）；
3. **联系走事件**：功能之间不直接函数调用，通过 `broadcast(type, payload)` + `events.jsonl` 传；
4. **工具即入口**：新能力暴露为 `ctx.tools.register` 的一个工具，名字 `guide_*` 或独立前缀；
5. **必须写文档**：本条 + CHANGELOG 四段式，缺一不可；
6. **不许做的事**：能力层直接依赖业务层、平台层读业务状态、绕过 state 写 UI。

## 6. 当前已知的脆弱点（转型时顺手修）

| 脆弱点 | 后果 | 建议 |
| --- | --- | --- |
| 浮层无热重载，改一行要重启 7 秒 | 迭代慢 | 做热重载（`dev-watch` 已有雏形） |
| state.json 全量轮询（300ms） | CPU 空转 | 改成变化才推 |
| PowerShell 5.1 读无 BOM 的 UTF-8 会乱码 | 改脚本踩坑 | 写脚本统一带 BOM |
| overlay 单实例互斥锁 | 两个插件不能同时起浮层 | 已用不同锁名绕开，需文档化 |
| 功能间直接调用（如 focus 调 plan） | 耦合，改一个崩一片 | 收敛到事件 |

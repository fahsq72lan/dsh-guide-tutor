## 一、为什么做这个

两个痛点，一句话：

1. **教学流程太贵**：每次判断「用户做完没/做对没」都要截图 + 主模型，一次教学 3–4 万 token，天天用不起。
2. **记录靠手写**：清单是计划，日记是回忆，两者对不上；想知道「19:50 那 25 分钟真的学日语了吗」，只能靠人记。

状态监测解决的是第 2 个，顺带为第 1 个铺路——**有了免费的时间线，才知道什么时候不该花 token 去看屏幕。**

---

## 二、核心设计：三层信号，成本递增

| 层 | 信号 | 成本 | 回答什么 | 这次做吗 |
| --- | --- | --- | --- | --- |
| **L1 进程层** | 前台进程、窗口标题哈希、是否全屏、时间戳 | 免费（每 3 秒一次查询） | **什么时候在做什么** | ✅ 重点 |
| **L2 动作层** | 键鼠空闲秒数（`idle.ps1` 已有） | 免费（实时） | 有没有在动 | ✅ 顺带 |
| **L3 内容层** | 截图 / OCR / 模型判断 | 花钱 | 做成了什么样 | ⬜ 暂不做 |

**原则**：L1 和 L2 能答的，绝不调 L3。教学流程里「该不该说话」「该不该截图」先在 L1、L2 判掉。

## 三、清单联动：这是这张表最值钱的部分

时间线只有和清单对上，才有意义。

```
清单（计划）                    时间线（实际）
19:50–20:15 日语 ①      ←→     19:50–20:02 chrome / 20:02–20:15 Edge
20:20–20:45 日语 ②      ←→     20:20–20:41 Code（写代码）
21:00–21:15 复盘         ←→     21:00–21:12 微信
```

**每条时间线自动挂上 `plan_item_id`**（落在哪个条目的时段里），于是自动得到三样东西：

| 产出 | 说明 |
| --- | --- |
| **对上了** | 时段内前台是预期应用（学日语 → Edge/Anki） |
| **偏了** | 时段内前台完全不符（计划学日语，实际在打游戏） |
| **空窗** | 计划有条目，但那个时段没有任何活动记录（人不在） |

**不评判、不提醒、只记录。** 晚上看这张表，比任何总结都诚实。

## 五、明确不做的（并写清原因）

| 功能 | 为什么不做 |
| --- | --- |
| **分心提醒**（切窗口超 5 次就提示） | 提醒本身就是打断，和「不打扰」冲突；而且切窗口 ≠ 分心（查资料、看文档都会切）。**记录可以，提醒不要。** |
| **自动场景判断决定教法**（检测到 IDE 就自动教编程） | 判断错一次就会误导整节课；用户要自己说学什么。**最多作为内部信号，不替用户做决定。** |
| **行为画像 / 睡眠推断 / 效率打分** | 越过「服务于当下」的边界，变成监控。**不做。** |
| **定时截图做感知哈希** | 截图有隐私成本，且 3 秒一次的 CPU 开销不值。**想要 L3 时按需单次截。** |

## 六、数据结构（草案）

`activity-YYYY-MM-DD.jsonl`，一行一条：

```json
{
  "t": "2026-11-13T20:41:03+08:00",
  "proc": "Code",
  "title": "sha256:3a7f9c…",
  "fullscreen": false,
  "idle_s": 4,
  "plan_item_id": "tmwc233oe"
}
```

- `title` **只存哈希**，原文不落盘（要分析内容时单独截图）；
- `plan_item_id` 当且仅当时间落在某条清单时段内才填，否则 `null`；
- 每行约 100 字节，一天约 2.8 万行 ≈ 2.8 MB，按天分文件即可。

**产出视图**（`/api/guide-coach/timeline?date=`）：

```json
{
  "date": "2026-11-13",
  "segments": [
    {"from": "19:50", "to": "20:02", "proc": "chrome", "plan_item_id": "tmwc233oe", "match": "偏"},
    {"from": "20:02", "to": "20:15", "proc": "msedge", "plan_item_id": "tmwc233oe", "match": "对"}
  ],
  "summary": {"planned": 6, "matched": 3, "off": 1, "idle": 2}
}
```

## 九、和教学流程的关系（为什么这是前置）

教学流程里最贵的三个判断：

| 判断 | 现在 | 有了时间线之后 |
| --- | --- | --- |
| 他还在做吗 | 定时截图 + 看图 | `idle_s` + 进程有没有变（**免费**） |
| 他做完了吗 | 主模型看整屏 | 窗口内容变化 + 进程切换（**降级为小判断**） |
| 他做对了吗 | 主模型看整屏 | 仍需 L3，但**只在「该检查」时才调** |

**结论：状态监测没做完之前，教学流程不要接**——否则就是拿大模型当秒表用。

## 0. 这个方案要解决什么

现在的流程是「学完 → 勾掉 → 结束」。学过的第 1 课、第 3 课语法，过两周会退化成「好像学过」。

这份方案要加一层**复习调度**：

```
学完一个叶子步骤 → 建一张卡 → 按遗忘曲线算下次到期 → 到期弹给你 → 你自评 记得/模糊/忘了 → 重算到期
```

它不重写派发，只是往现有派发链路里塞一个「复习包」条目，占当天配额的一部分。

## 1. 核心数学（✓ 已验）

### 1.1 遗忘曲线

```
R(t, S) = (1 + FACTOR × t/S) ^ DECAY      t 与 S 同为天，S > 0
FACTOR = 19/81，DECAY = -0.5
```

代 t = S 进去：`(1 + 19/81)^(-0.5) = (100/81)^(-0.5) = 9/10 = 0.9`。

意思是：**在稳定度 S 那一刻，你还能想起来的概率是 90%**。这是 FSRS 系列用的幂律形式，不是 `e^(-t/S)`。

### 1.2 反解间隔

```
I(r, S) = (S / FACTOR) × (r^(1/DECAY) − 1)
```

I(0.9, S) 应当正好等于 S（浮点误差 < 1e-9）。这是最容易写错的一处，必须单测。

### 1.3 新稳定度（答对之后）

```
S_Inc = 1 + k × ((11 − D)/10) × (S + 1)^(−0.15) × (exp(1.5 × (1 − R)) − 1)
S'    = S × S_Inc
k     = 8.0（记得） | 3.0（模糊）
```

三条单调性（✓ 已验，公式本身保证）：

| 性质 | 含义 |
| --- | --- |
| D 越大 → S_Inc 越小 | 越难的卡涨得越慢 |
| S 越大 → S_Inc 越小 | 稳定性会饱和，不会无限翻倍 |
| R 越小 → S_Inc 越大 | 快到遗忘边缘时复习，收益最大（间隔效应的来源） |

### 1.4 金标表（✓ 前 4 轮手算吻合）

G=3 连续复习，D 恒为 5，S₀ = 1.0，不吸附：

| 轮 | 到期（累计天） | S |
| --- | --- | --- |
| 0 | 0 | 1.0000 |
| 1（+30 分钟） | 0.02 | 1.0152 |
| 2 | 1.0352 | 1.7251 |
| 3 | 2.7603 | 2.8778 |
| 4 | 5.638 | 4.7016 |
| … | 17.85 | 11.746 |
| … | 47.60 | 26.959 |
| … | 114.05 | 57.32 |

容差 ±0.05 天 / ±0.5%。**表是推算值，与实现不一致时应修改实现，而非修改表。**

### 1.5 状态迁移（唯一入口 `applyGrade(card, G, now)`）

```
G = 1（忘了）
  S = max(0.3, S × 0.35)
  lapses += 1
  D = clamp(D + 1 × (10−D)/9, 1, 10)
  state = lapses ≥ 4 ? leech : relearning
  dueAt = now + 20 分钟

G = 2/3（模糊/记得）
  S = max(S, nextStability(S, D, R, G))
  reps += 1
  D = clamp(D − 1 × (G−3) × (10−D)/9, 1, 10)   // G=3 时 D 不变
  dueAt = now + min(I(0.9, S), 180 天)

每次之后：D = 0.02×5 + 0.98×D（向初始值缓慢回归）
leech 的卡 dueAt = null，移出队列，等人工处理
```

## 3. 落盘路径与派发配额

- 配额：`quota = min(3, floor(当天格数 × 0.25))`，8 格 → 2 格
- 每格 ≈ 4 张卡，所以一次派 8 格会生成一条「复习 8 张」的条目，`units = 2`
- 复习条目**不参与** `pickNextSteps` 的 p 排序
- 到期吸附：`snapToGrid()` 把到期时间对齐到半小时、限制在 08:00–22:30，避免「凌晨 3 点到期，早上 9 点已逾期 6 小时」

## 4. 与目标模块的协调

一句话原则：**目标是「学会」，复习是「不忘记」**。两套数据结构各管各的，只在六个点上对接。

### 4.1 六个接触点

| # | 接触点 | 改哪里 | 做什么 |
| --- | --- | --- | --- |
| 1 | 建卡来源 | `lib/decompose.js` 的 `leafSteps` + `index.js` 的 `onGoalStepChange` | 叶子 done 时建卡；组步本身不建 |
| 2 | 配额切分 | `index.js` 的 `goalCapacity` | 先切 25% 给复习，剩下派新步 |
| 3 | 复习包 | `index.js` 的 `autoPlanGoals` | 生成 `kind:"review"` 条目，`goalId: null` |
| 4 | 目标完成 | `lib/decompose.js` 的 `recomputeProgress` | **不改判定**，只加派生指标 `retention` |
| 5 | 删目标 | `index.js` 的 `dropGoalItems` | 追加：该目标的卡全部置 `suspended`，不删 |
| 6 | 看板 | `overlay.ps1` 的 `Get-GoalRows` | 行加 `reviewDue`，标题旁渲染徽标 |

### 4.2 卡怎么挂到目标树

复习卡只由**叶子**创建，创建时三个 id 一起拿到，不需要额外字段：

```
stepId "g4-m1-s1" → goalId "g4" + milestoneId "m1"
```

组步不建卡（它的 children 才是叶子）。级联完成的叶子各自建卡，重复建卡由 INV-1 吸收。

### 4.3 配额怎么分配

```
targetUnits = clamp(round(free × 0.6 / 30), 2, 10)     // 现有逻辑，不动
reviewQuota = min(3, floor(targetUnits × 0.25))
learnQuota  = targetUnits − reviewQuota

复习包：units = ceil(待复习张数 / 4)，封顶 reviewQuota
新步：  在剩下的 learnQuota 格里按 p 排序派发
```

**边界**：当天 `targetUnits ≤ 2` 时，复习优先（保本），新学习让位。

### 4.4 复习包不挂任何单个目标

一个复习包跨多个目标，塞不进单一 `goalId`：

```jsonc
{
  "title": "复习 8 张（学习 5 / 数据 3）",
  "kind": "review",
  "reviewIds": ["r-g4-m1-s1", "r-g4-m1-s2"],
  "goalId": null,        // 不挂，避免目标进度虚高
  "stepId": null,
  "units": 2,
  "auto": true
}
```

### 4.5 目标完成语义（待定，需人工拍板）

现在 `recomputeProgress` 是「所有步骤 done → 目标 done」。加了复习后有两个选择：

| 方案 | 判定 | 代价 |
| --- | --- | --- |
| **A. 复习不阻塞**（建议） | 步骤全 done → 目标 done；复习另算「保持度」 | 目标完成后仍能看到「12 张卡在复习」，但状态已是 done |
| **B. 复习阻塞** | 步骤全 done **且** 所有卡毕业 → 目标 done | 语义更严格，但「N1」这类目标可能永远完不成——考完之后还复习吗？ |

方案 A 的「保持度」是一行派生数据，不改 `status`：

```
目标：学习日语到 N1        [active]
  步骤 15/15 完成
  保持度：8 张卡在复习，平均稳定度 12 天，最近一次复习 11-24
```

**建议 A**：混在一起会让「完成」这个状态失去期限。

### 4.6 删目标时卡不删，置挂起

```
删目标 g4
  → 清掉清单里 g4 的条目              （现有 dropGoalItems 行为，保留）
  → review.json 里 goalId=g4 的卡 → state = "suspended"，dueAt = null
  → 卡片数据保留，可被 backfill 恢复
```

删数据不可逆，挂起可逆。

### 4.7 看板显示

```
完成 Python 的学习           0/6   ⟳ 2
                            ↑     ↑
                          步骤进度  今天 2 张到期
```

`⟳ 0` 时不显示；点徽标打开复习窗（§4.8 说的独立窗口）。

### 4.8 防复习淹没配额

单目标一次学 20 课，第二天可能 20 张卡同时到期，把配额吃光。除 T5 的目标轮转外，再加一条硬约束：

> **单个目标的复习量，不超过当天复习配额的一半。**

`reviewQuota = 2` 时，任何目标最多出 1 张，保证多目标都能轮到。

### 4.9 不会被影响的三处

- `availableSteps()` 的依赖过滤：复习不改 step 状态，不影响解锁。
- `pickNextSteps()` 的 p 排序：复习条目不参与。
- `skill.record`：INV-4 已规定复习结果不写 `user-skill.json`。

## 5. 我核对出的三处问题

### ① 建卡判据写错了（严重）

原文：「完成组步 → 一条都不多」。

但在这个系统里，**勾组步会级联把所有子步标成 done**，而子步正是叶子、正是 `read`/`drill`，**恰恰该建卡**。

照做会漏建卡，而且它把这条写进了 DONE 判据，等于把错误写进验收标准。

**应改为**：组步本身不建卡，被级联完成的叶子各自建卡（重复建卡由 INV-1 承受）。

### ② 复习卡的位置不对

原文：`card.mode = "review"`，追加到现有 mode 分派。

但现有卡片是「一个窗口换内容」（`plan|record|goals|history`），同时只显示一张。复习卡要的是**单独窗口、浮在最上层、一次一张、点完翻答案面**——应该像派发窗口那样独立开，不该和清单卡争同一个位置。

### ③ 题面来源不可靠

原文：`prompt = step.check`。

但 `check` 在这个系统里是**只校验非空、不做语义判断**的字段（用户明确要求）。它可能长这样：「能读课文并说出语法点」——这是能力描述，不是问题。用户盯着它没法回答「记得/忘了」。

原文设计的 `weak` 正则 `/^(能|要|会|掌握|理解)?[^,。;]{0,6}$/` 只能抓 6 字以内的短句，挡不住 11 字的能力描述。

**两条出路**：
1. 提高 `check` 的质量门槛（写题面式的检查句）；
2. 换题面来源——完成时让 AI 生成一张真正的问答对。

### 可以不管的两处

- T3「`clearAutoSteps` 放行复习条目」是多余的：复习条目 `stepId: null`，现有过滤 `i.auto && i.stepId && !i.done` 已经跳过它。
- T9「C++ 最小二乘拟合工具」：为一次拟合引入 VS2022 工具链，成本远大于收益，用 Python/Node 写 50 行更合适。

## 6. 待定项（原 spec 的默认值，偏激进）

| 问题 | 默认值 | 我的看法 |
| --- | --- | --- |
| 每天几格复习 | 25%，封顶 3 格 | 合理 |
| 有无考试期限 | 无 | 合理，先不锚 |
| 粒度 | 到「步」 | 默认值可以，但受问题三拖累 |
| **复习包被勾掉怎么算** | **包内全按「记得」结算** | **偏激进**，用户可能只是扫一眼。建议改为按「模糊」 |
| 存量目标要不要补卡 | 不补，backfill 只试运行 | 合理 |
| 参数能不能自动调 | 不能，只出报告 | 合理 |
| **复习是否参与目标完成判定** | **不参与（方案 A）** | **待你拍板**：A 不阻塞、B 阻塞，见 §4.5 |

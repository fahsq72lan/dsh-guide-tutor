## 0. 四期合起来在讲什么

四期正好是四层：

- **24 期**：每天用同一张时间表，什么时候学、什么时候休、什么时候可以浪费——解决「**节律**」。
- **41 期**：把一天切成 48 个半小时格，事后逐格记下实际做了什么——解决「**测量**」。
- **42 期**：同样的半小时格，事前逐格排好，到点无缝切换——解决「**执行**」。
- **43 期**：格子里放什么行动、被打断时走哪条路——解决「**判断**」。

合起来一句话：**把一天变成一个可预期的状态机**。24 期定骨架，41 期拿它量现实，42 期让它一格一格转起来，43 期管掉出状态后怎么回来。

## 1. 第 24 期：一天的计划表

### 1.1 作者的样板（假设 8 点自然醒）

| 时段 | 内容 | 性质 |
|---|---|---|
| 8:00–9:00 | 洗漱、吃饭、准备 | 休 |
| 9:00–12:00 | 学一（3h） | 学 |
| 12:00–14:00 | 吃饭、午休 | 休 |
| 14:00–17:00 | 学二（3h） | 学 |
| 17:00–19:00 | 晚饭、锻炼、纯玩 | 休 |
| 19:00–22:00 | 学三（3h） | 学 |
| 22:00–24:00 | 洗漱 + **浪费** | 浪费 |
| 0:00–8:00 | 睡觉 | — |

他画图用三种符号：**圈 = 休息，树干 = 正事，三角 = 浪费**。这个区分是整期最容易被忽略、但最有用的部分。

### 1.2 三条真正的规则（不是"有张表"就行）

1. **整点开始**。不整点开始就必然滑成"再等五分钟"，然后 40 分钟变 10 分钟。
2. **一小时为周期循环**：学 40 分钟、休 20 分钟，每小时一模一样。
3. **学必学，休可休**：
   - 40 分钟里只能学，不能拿"有急事"当借口；
   - 20 分钟里可以休、可以玩、也可以继续学；
   - 但学习不许挤进休息，休息也不许变成"假装在学"。

### 1.3 双重重复（结构上的巧思）

- **大重复**：一天三个「学 3 小时 + 休 2 小时」；
- **小重复**：每个 3 小时里，每小时都是「学 40 + 休 20」。

净学习量 = 9 小时 × 2/3 = **6 小时/天**。作者认为表面宽松、实际不低。

### 1.4 三个反直觉的设计

| 设计 | 他的理由 |
|---|---|
| **把「浪费」写进计划**（睡前玩手机固定在 23 点后） | 承认自己解决不了，就给它一个合法时段；"约定好的玩"换取其他时段不乱来 |
| **睡觉时间可浮动，起床时间固定** | 醒这件事会形成节律：工作日到点自然醒，周末想睡都睡不着 |
| **休息可延长，学习不可压缩** | 上午学到 11:40 就开始休了，午休常变 2.5 小时；但 9 点那段一分钟不能少 |

### 1.5 顺带回顾的简单方法

清单法、消除条件法（把游戏从电脑里移除）、增加促进动力法。

### 1.6 本期没讲的

「为什么有效」明确留到下一期。**所以它是样板，不是论证。**

## 2. 第 41 期：记录行动的用时

> 这是整套方法的「测量层」：先说清楚为什么要记、记完能干什么。他自己说是第 14/15 期的升级版——原理补全、方法简化。

### 2.1 记什么

**记「时间当中的行动」**：这半小时在干什么，而不是「干了多久」。

方法就三句话：

1. **固定起止**：整点到半点、半点到整点，一天切成 48 段，今天和明天划分完全一样；
2. **等长时段**：每段都是半小时；
3. **段内只记一个行动**：这半小时只做一件事。

再加两条升级：**连续记录**（整天都记，不只是记学习）；**直观化**（用表格，单元格长度就是时间长度）。

### 2.2 为什么是半小时

| 考虑 | 结论 |
|---|---|
| 专注 | 半小时能专注，一小时常常专注不了 |
| 记录负担 | 再短（如 10 分钟）负担太高，坚持不了 |
| 精度 | 一小时误差可达 20 分钟，半小时还可以 |
| 检查点 | 半点和整点会自然形成提醒点 |

他自己说得很直白：越短越容易专注，但记录负担越高；半小时是「专注、负担、精度」三者的折中。

### 2.3 六种用途（事前 1、当时 2、事后 3）

**事前**

1. **把自律目标量化**：「明天学 8 小时」＝ 16 个格子填「学习」。不记录，你根本没法检验。

**当时**

2. **给节点任务提供意识**：节点 = 整点和半点。「到点了该干什么」靠记录表在眼前不断提醒。
3. **给节点任务提供动力**：记录本身有动力，而这个动力会传染给节点任务。

**事后**

4. **回看产生大动力**：连续成功 → 挑战更高、自信增加；连续失败 → 大改变的动力（但持续不久，只适合「彻底卸载」「断关系」这类一击必杀的事）。
5. **发现现状 → 发现任务**：优先处理「影响大 + 能解决」的现状，当天复盘、第二天排进去。
6. **发现规律 → 形成方法**：把偶然的成功经验固定成可重复的方法。

### 2.4 两个关键概念：节点任务、导正序列

- **节点任务**：以整点半点为情景起始的任务，等于一天所有的计划（主序列 + 导正序列）。
- **主序列**：安排好的正轨。
- **导正序列**：偏离之后用来回到主序列的那条轨道。

这里有个很漂亮的推论：**只要你每个整点半点都「回来记录」，每次偏离就不会超过半小时**。

> 09:15 开始玩游戏 → 09:30 到点要记录 → 记录的动力把你从游戏里拉回来 → 15 分钟就回到正轨。**记录本身就是导正序列的触发器。**

### 2.5 怎么让「记录」这件事自己发生

- **意识**：记录表放最表层（纸质铺桌面、电子置顶）；意识预定（到点前就在心里想着）；闹钟（整点半点最好设）；实时监督（找个朋友在整点半点互提醒）。
- **动力**：影响价值（记录能影响别人）、害怕遗忘（每过半小时就永久失去这段时间的真相）、概括的乐趣、有观众（公开记录）。

> 这几条动力的说法偏宏大，实际最管用的是「害怕遗忘」和「置顶可见」。

### 2.6 与另外三期怎么接

| 期 | 层 | 一句话 |
|---|---|---|
| 24 期 | 骨架 | 一天长什么样 |
| 41 期 | **测量** | 怎么知道实际做了什么 |
| 42 期 | 执行 | 半小时一格怎么转起来 |
| 43 期 | 判断 | 格子里该放什么、偏了走哪条路 |

41 期和 42 期是同一套半小时格的两种用法：42 期是**事前**往里排，41 期是**事后**往里记——他说的「记录」，本质上就是「事后填同一张表」。

> 注意：41 期用的也是「固定起止 + 半小时」，和 24 期的「1 小时学 40 休 20」仍然对不上，再次印证 24 期是旧版。

### 2.7 一个必须点出的差异

他这套的效力，很大程度来自「**手动记录**」这个动作本身：到点要记 → 于是想起来 → 于是回来。而自动采集（比如咱们的记录卡）把这一步替你做了，**省了负担，也丢了「意识和动力」这一层**。

这不是 bug，是取舍：自动采集换来一天 48 次不用动手，代价是失去「记录即提醒」的导正作用。要补回来，得另外加「到点提醒」和「事前定目标」两个动作。

## 3. 第 42 期：用番茄做意识管理

> 这期是「执行层」：24 期给了骨架，这期讲骨架怎么一格一格走起来。**这里的「番茄」不是 25/5 的番茄工作法，是他自己的半小时格。**

### 3.1 意识管理是什么

- **意识信息**：每个当下感知到、且实践需要关注的那部分信息。
- **序列**：提前设计好的、意识信息出现顺序的**表征**（写下来的清单、表格、步骤）。
- **主序列**：连续不断的、通向目标的长序列。
- **导正序列**：已经偏离主序列时，用来回到主序列的序列。
- 序列按用途再分两类：**让行动出现**（自律）、**行动所使用的素材**（信息条件）。

一句话：**意识管理 = 让正确的信息在正确的时刻出现在意识里。**

### 3.2 简化版循环（四步）

1. **前一格快结束时**：安排下一格的行动；留意还有几分钟到下一格。
2. **下一格开始**：闹钟响 → **无缝转换**（停下当前行动，立刻执行安排好的行动）。
3. **格子进行中**：判别当前做的还是不是安排好的那件事（防偏）。
4. **快结束时**：回到第 1 步。

注意第 2 步的措辞：它不要求你「开始做某事」，只要求你**换掉当前这个**。这是从「意识无缝」推出来的：意识不可能空着，你不安排，别的东西就会填进来。

### 3.3 他的番茄特点

| 特点 | 说明 |
|---|---|
| 固定起止 | 整点到半点、半点到整点 |
| 半小时一格 | 不是 25/5，格内也不再单独留 5 分钟休息 |
| 连续铺满全天 | 从醒到睡，格子首尾相接 |
| 用闹钟不用计时器 | 靠绝对时点提醒，而不是相对倒计时 |

### 3.4 为什么必须是整点

- 整点/半点比「19:37 开始」更容易被注意到；
- 闹钟 + 心里的倒计时 = 双保险（没闹钟时靠主动看表，但不稳定）；
- 固定起止让「前一格结束」变成可预期的信号，而不是凭感觉。

### 3.5 格子里没动力怎么办

不是硬扛，而是执行一个**判断序列**：

- 当场制造动力（代价可接受）→ 制造；
- 制造代价太高、太耗时 → 直接转换行动。

作者自己承认：这套只解决「**想不起来**」，不解决「**不想做**」。动力那部分要另一套理论（对应 43 期的「自律」触发）。

### 3.6 石流（这个术语终于有了完整定义）

**石流 = 一天必做、按顺序、连续无缝、每天重复的一组行动。**

两个属性：

- **重复性**：每天都要做（锻炼、复习、背单词）；
- **连续性 + 有顺序**：一格接一格，不打乱。

有顺序的两个好处：对联想友好（按顺序回忆更容易）；前后行动之间有促进关系（前一个为后一个创造条件）。

> 42、43 两期都在讲同一个词，**这是作者的固定术语，不是字幕偶然**。但音近词仍不确定（疑为「流程」一类），引用时以「每天重复、按顺序、无缝」这组特征为准。

### 3.7 与前两期的关系（含一处矛盾）

| 期 | 颗粒度 | 主张 |
|---|---|---|
| 24 期（2023） | **1 小时** | 整点开始，学 40 分钟 + 休 20 分钟 |
| 42 期（2024） | **半小时** | 整点/半点各一格，格内不休息 |
| 43 期（2024） | 半小时 | 用格子做「必做 / 触发」的判定 |

> **矛盾**：24 期的「40+20」跨越了整点和半点，和 42 期的「半小时一格」对不上。按发布时间，42 期更新，**应是方法演进后的版本**。本文件以 42/43 期的半小时格为当前版本，24 期的 40/20 视为旧版细节。

## 4. 第 43 期：周期计划结构

### 4.1 定义

三个词拆开：

- **周期**：一组事件按顺序重复出现，完成这组事件的时间。这里取「天」——因为社会节律和生理节律都按天走。
- **计划**：对未来要做的行动做**选择**，并把它**表征**出来（写下来、符号化）。"真正的行动在第二天才会出现，计划只是它的代表。"
- **结构**：各部分之间的相互关系。

合起来：**给"一天的计划"定一个固定的分类框架**，目的是让"该做某个行动"这件事在该出现的时候能被想起来。

### 4.2 五组分类（结构的来源）

1. **周期必做 vs 周期可能做**（必然发生 vs 情景触发才发生）
2. **周期重复 vs 一次性**（每天做 vs 只做一次）
3. **主序列 vs 导正序列**（按计划走 vs 已偏离、需要拉回）
4. **确定的主序列 vs 可能的主序列**（第 3 组再分）
5. **优先 vs 保证**（对序列的更改 vs 偏离后的补救）

### 4.3 简版结构树

```
一天的计划
├─ 周期必做（情景确定 → 能提前排）
│   ├─ 石流：每天重复、按顺序的行动（复习、锻炼、背单词）
│   └─ 普通：一次性任务
└─ 周期触发（情景不确定 → 出现了才做）
    ├─ 优先（要改后续序列）
    │   ├─ 战略：来了新信息，原计划要变
    │   └─ 自律：计划没动力，明知该做却做不动
    └─ 保证（导正序列）：已长时间偏离主序列（游戏、手机、聊天、情绪）
```

> **术语说明**：「石流」是字幕音译（疑为「流程」一类），但 42、43 两期反复出现，是作者的固定术语，不是偶然错字。完整定义见第 2.6 节。

### 4.4 两种使用方式

**用法一：定接下来一段时间做什么**

只从「必做」里挑，按石流的顺序往下排。作者的"番茄"是**半小时一格，整点到半点，全天无空隙、休息也在这半小时里算**。

- 9:00 这个情景 = 每天做事的开始（强行规定为某个整点或半点）→ 做石流第一项（他的例子：复习）
- 9:30 = 前一格时间已过、任务已完成 → 做石流下一项
- 10:00 = 继续下一项

**用法二：情景出现就改当前行动**

| 情景 | 触发 | 动作 |
|---|---|---|
| 9 点该复习，但没动力 | 优先 → 自律 | 给"复习"制造动力 |
| 9:30 该锻炼，但困了 | 优先 → 战略 | 战略思考：睡一觉还是闭眼歇 |
| 10 点该背单词，却在打游戏 | 保证 | 从偏离状态拉回主序列 |

### 4.5 精髓

**先判断大类，再判断小类**。总共五种情况，先粗后细，判断成本才低；直接训练到"具体小类"成本太高且容易乱。

> [38:32] 原话：「先大结构……先明确大类，再在大类当中确定小类。」

### 4.6 作者自己的两个判断

- **自律是战略的特例**：计划没动力 = 一条新信息，它让原计划执行不下去，所以要改成"先制造动力"。
- **战略才是最关键的**：「讲了很多自律，其实战略才是最关键的。」本期侧重自律，战略留到战略理论讲。

### 4.7 他自己也承认

> [39:01]「肯定不是很好懂，因为纯理论，后续再有实践的案例。」

## 5. 能借的 / 不能照搬的

### 5.1 能借

- **两级判断**：先问"是在推进还是出了状况"，再问"哪种状况"。这是可实现的判定逻辑。
- **必做 / 触发分离**：现在的清单把吃饭、任务、临时起意混在一列，分开后"对上"判定才说得清。
- **石流 ≈ 习惯**：现有清单里没有"每天固定要做"的稳定项，全是每天现排的一次性任务，这条最缺。
- **"计划要被想起来"**：功能设计上等于「在正确的时间把正确的条目顶到眼前」。

### 5.2 不能照搬

| 问题 | 说明 |
|---|---|
| 术语自造且不稳定 | 石流/导正/保证/优先，用户记不住。**产品里必须换成人话** |
| 过度分类 | "困了不适合锻炼"要触发"战略思考"，是把常识包装成理论 |
| 五层判断对人太重 | 人做不到每次卡住都走一遍。**该由 AI 代办，而不是让用户判断** |
| 两期自相矛盾 | 24 期说"简单固定就够了"，43 期给了金字塔，复杂度差一个量级 |
| 没有"做不到"的处理 | 全篇假设会照做；连续三天没执行，分类就废了。"保证"是事后补救，不是预防 |

## 6. 落到 guide-tutor 的映射（尚未实现，设计稿）

### 6.1 数据结构

| 概念 | 现在的实现 | 建议 |
|---|---|---|
| 周期必做·石流 | 无 | 新增「每日常项」：`{ id, title, goalId?, order, enabled }`，每天自动出现在清单顶部 |
| 周期必做·普通 | `plan.json` 的 `items` | 保留；`goalId` 已在 schema 里但没人填 |
| 触发·自律 | 无 | 由记录卡检测：某条目连续未开始 / 空闲比高 → 提动力 |
| 触发·战略 | 无 | 计划变更事件（用户改清单 / 课表冲突）→ 重排当日 |
| 触发·保证 | 记录卡的 `match='清单内·别的'` / 空闲段 | 偏离累计超过阈值（待定 30 分钟）→ 拉回提示 |

### 6.2 判定伪代码（供后续实现参考）

```
function decide(now, todayItems, seqItems, recentSegs):
    # 1. 大类：此刻应该推进，还是处理状况？
    if no current slot or slot is rest/waste:
        return { kind: 'idle', next: nextSlotStart(now) }

    # 2. 出了状况吗？
    if recentSegs shows 偏离主序列累计 >= 30min:
        return { kind: 'recover', action: '拉回：离开当前应用，回到 ' + currentSlot.task }

    if currentSlot.task exists and 有动力(未连续拖延 >= 2 次):
        return { kind: 'proceed', task: currentSlot.task }

    if currentSlot.task exists and 没动力:
        return { kind: 'boost', task: currentSlot.task, how: '拆小 / 降门槛 / 即时反馈' }

    # 3. 计划本身要变？
    if 今天有变更(课表冲突 / 用户改单 / 新目标):
        return { kind: 'replan', reason: ... }

    # 兜底
    return { kind: 'proceed', task: nextSeqOrItem() }
```

### 6.3 与 A 类设计的关系

- 时间表模板（骨架）= 24 期；
- 每日常项（石流）+ 今日条目（普通）= 43 期的"必做"；
- 三种触发 = AI 加工真正要做的判断；
- **不要**把五个术语暴露给用户，面板上最多显示"现在该做什么"。
